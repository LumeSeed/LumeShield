# LumeShield 微光盾

让防护可观察、可调整、可恢复。

作者：**[LumeSeed](https://github.com/LumeSeed)**  
版本：**1.2.0**  
代码注释、管理页面和提示使用中文。

面向 WordPress 单站的轻量请求防护插件。以“先观察 → 核对业务 → 调整策略 → 开启拦截”的工作流程组织功能，提供请求检测、可信代理解析、访问名单、限流、脱敏日志和运行检查。无需修改主题，也不依赖外部防护服务。

## 1.2.0 新功能

新增微光盾星光拦截页，按实际命中类型显示标题，底部展示 RAY ID、IP、区域，适配 PC 与手机。不提供返回首页或帮助按钮，不模拟人机验证。升级说明见 [UPGRADE-1.2.md](UPGRADE-1.2.md)。

## 1.1.0 新功能

新增登录失败限速、Cloudflare 官方网段一键更新、按方法/路径/字段/规则设置的精细例外，以及不写日志的后台策略试测。升级与用法见 [UPGRADE-1.1.md](UPGRADE-1.1.md)。

## 安装

1. WordPress 后台 → **插件 → 安装新插件 → 上传插件**。
2. 下载 [WordPress 安装包](dist/lumeshield-wordpress-1.2.0.zip)，在文件页面点击下载，然后上传 ZIP 并启用。
3. 打开 **设置 → LumeShield 防护**。
4. 默认是**观察模式**：记录命中，保持业务响应。先检查登录、评论、编辑器、表单和支付回调是否正常，再切换为拦截模式。

也可以解压，将 `lumeshield/` 文件夹上传到 `wp-content/plugins/` 后在后台启用。不要把 ZIP 内文件散放到插件根目录。

## 环境要求

- WordPress 6.0 或更高版本，**单站模式**。
- PHP 8.0 或更高版本，启用 `mbstring` 与 WordPress 所需数据库扩展。
- 使用 WordPress 标准 MySQL/MariaDB 数据库驱动，数据库账号需要建表权限。
- 本版不支持多站点网络或第三方 SQLite 数据库替代层。

实测环境：WordPress 6.8.3 / PHP 8.3.36 / MariaDB 11.4.5。最低版本仅为代码目标，不代表每种组合都已实测。

## 功能

| 功能 | 行为 |
| --- | --- |
| 请求检测 | 检查 URI、参数名、GET/POST/Cookie、JSON 和适用的原始请求体 |
| 规则 | SQL 注入、脚本标签/事件属性、代码执行、路径穿越、敏感文件探测、扫描器 UA |
| IP 名单 | 精确 IPv4/IPv6 与严格校验的 CIDR |
| 路径名单 | 精确路径或末尾 `*` 前缀匹配，不接受任意正则 |
| UA 名单 | 忽略大小写的普通子串，不把 curl、WordPress 等常见客户端默认视为攻击 |
| 可信代理 | 仅直接连接地址在可信网段时读取选定代理头；XFF 从右向左解析 |
| 请求限流 | 数据库原子累加的固定时间窗计数，默认每 IP 每 60 秒 120 次 |
| 日志 | 查询、分类过滤、删除、清空、一键拉黑 IP；相同命中聚合计数 |
| 生命周期 | 启用建表、停用取消定时任务、卸载按设置选择保留或删除数据 |

## 设计原则

- **看得见状态**：运行检查页分别说明紧急开关、执行模式、数据表、可信代理与清理计划，不以一个笼统的“安全”分数代替事实。
- **先验证再拦截**：首次启用只观察，保留站点业务响应；站长结合真实日志决定是否开启拦截。
- **按 WordPress 方式管理**：配置使用 Settings API，写操作验证管理员权限与 nonce，停用和卸载具有明确的数据保留规则。
- **有限资源内检查**：保留嵌套字段路径，扫描解码后的 JSON，明确处理请求大小和结构上限。
- **只保存必要线索**：数据库保存脱敏命中记录，不保存原始载荷；相同事件聚合，自动清理旧数据。
- **故障可恢复**：管理员后台保留操作通道，配置常量可紧急停用；底层故障会显示降级提示。

模块职责、决策顺序与取舍见 [DESIGN.md](DESIGN.md)。

## 运行检查

打开 **设置 → LumeShield 防护 → 运行检查**，查看当前实际执行模式、数据库可读状态、清理任务和代理信任配置。检查页仅展示状态，不自动修改策略，不将历史故障记录直接当作已恢复。

任务“已安排”不等于一定执行成功；禁用 WP-Cron 时需要自行安排系统任务。数据库检查仅证明表可读取，不代表每种写入操作均可执行。可在日志页发起数据表修复，修复前不要清空有用日志。

## 名单优先级

1. 已认证且拥有 `manage_options` 权限的管理后台请求放行。
2. IP、路径、UA 黑名单。
3. IP、路径白名单：跳过后续内容检测和限流。
4. 请求限流与内容检测。

UA 白名单只跳过扫描工具 UA 识别，参数检测和限流仍执行。观察模式下黑名单和超限也只记录，不阻断。

每种名单最多 200 条，每行一条，`#` 开头表示注释。例如：

```text
# IP / CIDR
192.0.2.5
2001:db8::/32

# 路径（在路径名单中填写）
/private
/private/*
```

以上 IP 是文档示例，不应直接复制为可信代理。可信代理名单填写实际反向代理的回源地址，代理必须覆盖客户端伪造的头。使用 Cloudflare 时需维护实际回源网段并限制源站直连；可在“维护与试测”中手动同步官方网段；未提供定时自动更新。

## 响应与检测上限

拦截模式下：规则或黑名单命中返回 **403**，频率超限返回 **429** 并附带 `Retry-After`，长度或结构超限返回 **413**，无效 JSON 或不支持的压缩请求体返回 **400**。AJAX、JSON 和常见 REST 请求返回 JSON 错误；其他请求使用所选的星光拦截页或 WordPress 简洁页面。

默认请求体/单字段上限为 256 KiB，最多可调整到 1 MiB。参数结构深度限制为 16，最多 2048 个结构节点、1024 个检测条目，总扫描文本预算为单字段上限的四倍。超限在观察模式只记录，在拦截模式明确拒绝，不会被当成完整检查通过。

Multipart 文件上传只检查 PHP 已解析的表单字段与文件名，**不扫描文件内容**。PHP 在插件加载前截断的参数、丢弃的上传内容及服务器自身限制，需要另外配置和验证。

限流使用固定时间窗，窗口交界处可能短时间允许接近两倍阈值；不是严格滑动窗口。共享出口的用户使用同一 IP，阈值需要结合站点业务调整。

## 日志与隐私

日志保存在 WordPress 数据库的 `前缀lumeseed_lumeshield_logs` 表；限流数据保存在 `前缀lumeseed_lumeshield_rates` 表，IP 计数键使用带站点密钥的 HMAC。

- 默认保留 7 天，最多 5000 条聚合日志，可在后台调整。
- 同 IP、规则、路径和处理方式在 5 分钟内合并计数。
- 每分钟最多执行 120 次日志记录；超过预算仍作出拦截决定，但不继续写日志。
- 记录 IP、方法、去除查询参数后的路径、规则、时间与处理方式，不保存请求体和命中值。
- 路径中的长标识段会遮盖，但短路径片段仍可能含个人信息，应结合站点 URL 设计评估。
- 每五分钟计划清理过期计数和日志，也可手动清理。WP-Cron 依赖访问触发，关闭或延迟执行时应由系统任务触发 WordPress Cron。

日志是有采样与聚合的检测记录，不是完整访问统计或审计归档。插件不向第三方发送日志或其他遥测数据。

## 紧急停用与卸载

若误拦导致无法操作，可在 `wp-config.php` 的 WordPress 加载语句之前加入：

```php
// 临时关闭 LumeShield，恢复访问后排查配置。
define('LUMESHIELD_DISABLE', true);
```

也可以通过文件管理器将 `wp-content/plugins/lumeshield/` 重命名，停用插件。

正常停用会保留数据；默认删除插件也保留数据。若要彻底清理，先勾选“删除插件时同时删除策略与日志”并保存，再停用并删除插件。此操作不可恢复。

## 防护边界

本插件在 WordPress `init` 阶段执行，PHP 和 WordPress 已经开始运行，其他插件更早执行的逻辑不在它的前置保护范围内。直接访问静态文件、其他 PHP 入口、提前返回的页面缓存，以及未进入 WordPress 的请求都可能绕过插件。

规则匹配存在误报和漏报，不代替应用代码修复、输出转义、数据库参数绑定、上传检查、CDN/服务器限流或专业边缘 WAF。数据库/引擎异常时采取保可用的放行降级策略，后台显示警告；已确认的拦截不会因为日志写入失败而取消。

本版没有基于攻击次数的自动 IP 封禁、验证码挑战、恶意文件扫描或第三方规则订阅，不宣称能抵御所有攻击。
